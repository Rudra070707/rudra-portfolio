The portfolio should demonstrate engineering ability through **real projects, accurate information, thoughtful design, and quality implementation**.

# 20. Visual Requirements

* Minimal

visual direction.

# 21. Animation Requirements

Animation should be subtle and purposeful.

Preferred effects include:

* CSS transitions
* Hover states
* Small entrance animations
* Limited scroll reveals
* Small transforms

The implementation must respect:

```css
prefers-reduced-motion
```

Animation should never be required to understand content or use the website.

# 23. Accessibility Requirements

Accessibility is a first-class requirement.

The website must support:

* Semantic HTML
* Logical heading hierarchy
* Keyboard navigation
* Visible focus states
* Sufficient color contrast
* Accessible links and controls
* Appropriate image alt text
* Reduced-motion preferences
* Responsive touch targets

Use native HTML semantics wherever possible.

ARIA should only be used when necessary.

---

# 24. Performance Requirements

The portfolio should be lightweight and fast.

Priorities:

* Fast initial rendering
* Optimized images
* Minimal JavaScript
* Minimal unnecessary dependencies
* Efficient component rendering
* Appropriate lazy loading
* Efficient animations

### Lighthouse Targets

Target:

```text
Performance:      >= 90
Accessibility:    >= 90
Best Practices:   >= 90
SEO:              >= 90
```

These are quality targets rather than guaranteed scores.

Performance must be validated using actual measurements rather than assumed.

# 30. Dependencies

# 35. Product Principles

The portfolio should follow these principles throughout development:

### Build for the real user

Optimize the experience for recruiters, engineers, and professional visitors.

### Show real work

Projects and engineering work are more important than decorative claims.

### Keep it honest

Never fabricate experience, metrics, skills, or achievements.

### Keep it fast

Performance is part of the product, not a final optimization step.

### Keep it accessible

Accessibility is part of the definition of done.

### Keep it maintainable

Prefer simple architecture and understandable code.

### Add complexity only when justified

Do not build infrastructure for hypothetical requirements.

### Let the work speak

The portfolio should demonstrate engineering quality through its projects, implementation, and attention to detail rather than excessive visual effects.
